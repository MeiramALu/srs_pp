# SIW 2 — сравнение OpenMP и MPI: полное объяснение

Файл для понимания: **что требовалось**, **что сделано**, **что получилось** и **как это защищать**.

## 1. Что это за задача (простыми словами)

Есть два основных способа заставить программу работать на нескольких ядрах/компьютерах одновременно:

| | OpenMP | MPI |
|---|---|---|
| Память | **Общая**: все потоки видят все данные | **Раздельная**: у каждого процесса свои данные, обмен — только сообщениями |
| Как пишут | Добавляют директивы (`#pragma omp parallel for`) в обычную программу | Пишут программу, где каждый процесс знает свой номер (`rank`) и явно шлёт/принимает данные |
| Где работает | В пределах одного компьютера (узла) | От одного компьютера до кластера |
| Главная опасность | Гонки данных, ложное разделение (false sharing) | Взаимная блокировка из-за порядка Send/Recv, дорогие обмены |

**Задание SIW 2** — не пересказать теорию, а **провести эксперимент**: взять один алгоритм, написать его тремя способами (OpenMP, MPI, гибрид MPI+OpenMP), всё измерить на своей машине и **цифрами** ответить, когда какая модель лучше. В задании прямо сказано: работа без собственных измерений не получит полный балл за анализ.

## 4. Что реализовано

**Алгоритм:** уравнение теплопроводности `u_t = a·u_xx`, явная схема: каждый узел на новом шаге = старое значение + `0.25·(левый − 2·центр + правый)`. Чтобы посчитать крайний узел своей части, нужен узел соседа — отсюда **обмен**.

- **OpenMP**: каждый поток считает свой блок, между шагами барьер.
- **MPI**: область разрезана на полосы по рангам, на шаг — два `MPI_Sendrecv` для обмена границами.
- **Гибрид**: процессы MPI + потоки OpenMP внутри; обмен делает главный поток (`MPI_THREAD_FUNNELED`).
- **Одно и то же ядро** `kernel()` во всех трёх — чтобы сравнивать модели, а не арифметику.

## 5. Результаты (кратко и честно)

Машина: i5-13400F (16 аппаратных потоков), WSL2 Ubuntu 24.04, gcc 13.3, Open MPI 4.1.6.

1. **Корректность:** L∞ = 0 для всех 15 конфигураций — результат совпал с эталоном побитово (в алгоритме нет редукций, порядок операций один и тот же).
2. **Режим А** (N = 2^24, данные не помещаются в кэш): ускорение упирается в ≈ **1,5** — потолок задаёт **пропускная способность памяти**, а не модель программирования. OpenMP ≈ MPI ≈ гибрид (разница 1–9 %).
3. **Режим Б** (N = 2^18, данные в кэше): S(4) ≈ 3,1, S(8) ≈ 4,1 (эффективность ≈ 0,5). Опять три модели почти неотличимы. При p = 16 — деградация и большой шум (два потока на ядро + Windows), выводы по этой точке малодостоверны.
4. **MPI ping-pong:** `ts ≈ 0,23 мкс` (сообщение 1 байт), `B ≈ 14–16 ГБ/с`, `M* = ts·B ≈ 3…19 КиБ` (две подгонки: Open MPI меняет протокол около 4 КиБ, поэтому одна прямая описывает данные приближённо). Это обмен **через разделяемую память внутри узла**, не сеть кластера. Граничное сообщение (8 байт) ≪ `M*` — чистая латентность.
5. **Гибрид:** режим А — все деления одинаковы (0,81–0,83 с); режим Б — лучшее 16×1 (0,34 с), худшее 1×16 (0,46 с). Причина: один сокет и один NUMA-домен — главные аргументы за гибрид не работают, а схема FUNNELED добавляет ожидание.
6. **Память:** 16 MPI-процессов занимают на ≈ 243 МиБ больше, чем 1 процесс × 16 потоков (≈ 15 МиБ на процесс — среда выполнения MPI). Решающим это становится при рабочем наборе ≲ 0,25–1 ГиБ на узел или при реплицируемых данных. Сами данные при декомпозиции не дублируются.
7. **False sharing:** замедление до ×1,9 в простом тесте (шумное, но направление эффекта подтверждено).

**Вывод:** для такой задачи на одном узле — OpenMP (проще, не медленнее, меньше памяти); для кластера — MPI; при нескольких NUMA-доменах или нехватке памяти — гибрид. Железо (шина памяти, SMT) повлияло на результат сильнее, чем выбор модели.

## 8. Подсказки для защиты

- **Почему L∞ = 0?** Один порядок операций в каждом узле, редукций нет.
- **Почему ускорение всего 1,5 в режиме А?** Задача упирается в память: ≈ 24 байта трафика на обновление узла; одна нить уже даёт ≈ 34 ГБ/с.
- **Почему гибрид не выиграл?** Нет NUMA/нескольких сокетов; выигрыш гибрида — на кластере и по памяти.
- **Что значит `M*`?** Длина сообщения, при которой `ts = M/B`: короче — платим латентность, длиннее — пропускную способность.
- **Почему 248 МиБ у MPI на крошечной задаче?** ≈ 15 МиБ на процесс — среда выполнения.
- **Что бы вы измерили дальше?** Кластер из ≥ 2 узлов, NUMA-узел с first touch, MPI+GPU.
